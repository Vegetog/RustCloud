## 二、技术选型

| 层次 | 技术 | 选型理由 |
|------|------|---------|
| 后端语言 | Rust | 内存安全、高性能、零成本抽象 |
| Web框架 | Axum | 类型安全、高性能、良好的中间件支持 |
| 异步运行时 | Tokio | Rust 生态最成熟的异步运行时 |
| ORM | SeaORM | 类型安全、异步支持、代码生成 |
| 数据库 | PostgreSQL | 成熟稳定、功能丰富、事务支持 |
| 缓存 | Redis | 高性能、支持多种数据结构 |
| 对象存储 | MinIO | S3兼容、易于部署、开源免费 |
| 对称加密 | AES-256-GCM | 认证加密、硬件加速、安全标准 |
| 非对称加密 | RSA-2048 | 广泛支持、Web Crypto API 兼容 |
| 密钥派生 | Argon2id | 抗GPU/ASIC攻击、内存硬化 |
| 前端框架 | React | 生态丰富、组件化、TypeScript支持 |
| 客户端加密 | Web Crypto API | 浏览器原生、硬件加速 |

## 四、数据流概览

### 4.1 写入流程（上传）

```
用户 → 选择文件 → 生成文档密钥(DEK) → AES加密文件内容
     → 用公钥加密DEK → 上传{加密内容, 加密DEK, 哈希}
     → 服务器存储
```

### 4.2 读取流程（下载）

```
用户 → 请求文件 → 服务器返回{加密内容, 加密DEK}
     → 用私钥解密DEK → 用DEK解密文件内容
     → 验证哈希 → 展示/保存
```

### 4.3 分享流程

```
场景A - 分享给注册用户:
所有者 → 用私钥解密DEK → 用接收者公钥重加密DEK → 存储新密钥记录

场景B - 公开链接:
所有者 → 生成分享密钥 → 用分享密钥加密DEK → 生成链接(token#shareKey)
访问者 → 提取shareKey → 解密DEK → 解密文件
```

## 五、密钥层级

```
┌──────────────────────────────────────────────────────────────┐
│  用户密码 (User Password)                                     │
│  └── 用户输入，不存储                                          │
└──────────────────────────────────────────────────────────────┘
                    │
                    │ Argon2id (salt, 64MB内存, 3次迭代)
                    ▼
┌──────────────────────────────────────────────────────────────┐
│  主密钥 (Master Key) - 256-bit                                │
│  └── 仅客户端内存，会话结束清零                                 │
└──────────────────────────────────────────────────────────────┘
                    │
                    │ AES-256-GCM 加密
                    ▼
┌──────────────────────────────────────────────────────────────┐
│  用户私钥 (User Private Key) - RSA-2048                       │
│  └── 加密后存储在数据库                                        │
└──────────────────────────────────────────────────────────────┘
                    │
                    │ RSA-OAEP 解密
                    ▼
┌──────────────────────────────────────────────────────────────┐
│  文档密钥 (Document Key/DEK) - 256-bit                        │
│  └── 用用户公钥加密后存储                                      │
└──────────────────────────────────────────────────────────────┘
                    │
                    │ AES-256-GCM 加密
                    ▼
┌──────────────────────────────────────────────────────────────┐
│  文档内容 (Document Content)                                  │
│  └── 加密后存储在对象存储                                      │
└──────────────────────────────────────────────────────────────┘
```

## 六、创新点

### 6.1 零服务端存储密钥管理

**问题**: 传统方案 Master Key 存储在 KMS/HSM，存在单点故障和泄露风险

**方案**:
- Master Key 仅在客户端内存中存在
- 注册时：密码派生 Master Key → 加密私钥 → 只存储加密私钥和 salt
- 登录时：重新派生 Master Key → 解密私钥成功即验证密码正确
- 退出时：清零内存中的 Master Key

**收益**: 即使服务器被攻破，攻击者也无法解密用户数据

### 6.2 分层威胁防护模型

```
┌─────────────────────────────────────────────────────────────┐
│ 第1层 - 客户端防护                                           │
│ 威胁: 键盘记录、恶意软件、XSS                                 │
│ 防护: 密钥清零(zeroize)、Web Crypto API、CSP策略             │
├─────────────────────────────────────────────────────────────┤
│ 第2层 - 传输层防护                                           │
│ 威胁: 中间人攻击、流量分析、重放攻击                          │
│ 防护: TLS 1.3、证书固定、时间戳+Nonce验证                    │
├─────────────────────────────────────────────────────────────┤
│ 第3层 - 服务端防护                                           │
│ 威胁: SQL注入、权限绕过、DDoS                                │
│ 防护: 参数化查询、权限中间件、限流                            │
└─────────────────────────────────────────────────────────────┘
```

### 6.3 基于密码学的细粒度权限控制

**问题**: 传统方案权限仅靠数据库记录，可被绕过

**方案**:
- 权限通过密钥分发实现：无密钥 = 无法解密 = 无权限
- 授权：用接收者公钥加密文档密钥
- 撤销：删除密钥记录，可选密钥轮换

**权限级别**:
| 级别 | 权限 | 实现 |
|------|------|------|
| 所有者 | 完全控制 | 原始文档密钥 |
| 编辑者 | 读写 | 重加密密钥 + 编辑标记 |
| 查看者 | 只读 | 重加密密钥 |
| 预览者 | 预览 | 低质量版本密钥 |

## 七、数据库表结构概览

```
users
├── id (UUID)
├── email (唯一)
├── password_hash (Argon2)
├── salt (密钥派生)
├── public_key (RSA公钥)
├── encrypted_private_key (加密的私钥)
├── private_key_nonce (加密Nonce)
└── created_at, updated_at

documents
├── id (UUID)
├── owner_id (外键 → users)
├── encrypted_name (加密的文件名)
├── content_hash (SHA-256)
├── storage_path (存储路径)
├── size (文件大小)
└── created_at, updated_at

document_keys
├── id (UUID)
├── document_id (外键 → documents)
├── user_id (外键 → users)
├── encrypted_key (用用户公钥加密的文档密钥)
├── permission_level (权限级别)
└── created_at

share_links
├── id (UUID)
├── document_id (外键 → documents)
├── creator_id (外键 → users)
├── access_token (访问令牌)
├── encrypted_key (用分享密钥加密的文档密钥)
├── password_hash (可选密码)
├── expires_at (过期时间)
├── max_access_count (最大访问次数)
└── created_at
```
